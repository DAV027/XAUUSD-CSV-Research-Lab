# Edge D v1 — Session Liquidity Sweep → Reclaim Reversal

Date: 2026-09-17
Status: frozen design pending implementation-plan approval
Branch: `research/edge-d-session-sweep-reclaim-v1`

## Research purpose

Edge D is a new, independent XAUUSD M1 research family. It must not be treated as a retune of Edge A, Edge B, or Edge C.

The hypothesis is that a major session may sweep a causally known liquidity level from the immediately preceding reference session, fail to hold beyond that level, then reclaim it and reverse. The research objective is to test whether that event contains positive after-cost expectancy with adequate sample size and robustness.

`$50/day` remains a later portfolio/business objective. It is not a sampler target, activation target, strategy threshold, or promotion criterion.

## Why this is independent

Existing repository strategies already test generic session-open momentum, prior-session high/low breaks, opening-range breakouts, rolling price-action level sweeps, statistical continuation/reversal, mean reversion, volatility, and breakout families.

Edge D is different because its entry condition is a stateful cross-session event:

1. construct a causally available reference range,
2. freeze that range at target-session start,
3. observe a sweep beyond one side,
4. require a reclaim back through the frozen level,
5. enter opposite the failed sweep,
6. allow at most one signal per transition.

A generic break, wick, or rolling-high/low reclaim is not sufficient.

## Frozen transitions

Exactly two transition types are sampled in v1:

### `asia_to_london`

Reference range:
- high/low accumulated during the completed Asia session immediately preceding the target London session.

Target window:
- the London session immediately following that Asia reference.

At the first London target bar, freeze:
- reference high,
- reference low,
- lagged ATR reference,
- target-session bar counter.

### `london_pre_ny_to_new_york`

Reference range:
- London-session high/low accumulated only up to, but excluding, the first New York target bar.

Because London and New York overlap, the reference is frozen at the first New York bar. Any later London price action is ignored for that transition's reference range.

Target window:
- New York session beginning at that first New York bar.

At the first New York target bar, freeze:
- London high/low accumulated through the immediately preceding bar,
- lagged ATR reference,
- target-session bar counter.

If no valid reference range exists at target start, that transition produces no signal.

## Frozen ATR semantics

The episode ATR reference is the most recent finite positive `atr14` value available strictly before the target-session start bar.

Once the target transition is armed, this ATR value is fixed for the entire transition. It is not recomputed after the sweep or reclaim.

This prevents future volatility information from changing already-armed thresholds.

## State machine

Each transition is independent and may emit at most one trade signal.

### 1. Build reference

Track the reference high and low as defined by the selected transition.

### 2. Arm

At target-session start, if reference high/low and lagged ATR are valid:

- freeze reference high/low,
- freeze ATR,
- reset sweep state,
- set target bar index to zero,
- arm the event.

### 3. Entry-window expiry

Only bars with target bar index `< entry_window_bars` are eligible to create a new sweep or reclaim confirmation.

When the entry window expires, the transition is dead and cannot rearm until the next qualifying session transition.

### 4. Sweep detection

Upper sweep condition:

`high > reference_high + sweep_atr * frozen_atr`

Lower sweep condition:

`low < reference_low - sweep_atr * frozen_atr`

A sweep is recorded using intrabar high/low; no signal is emitted yet.

### 5. Ambiguous double-sweep invalidation

If both reference sides have been swept before a valid reclaim confirmation is emitted, the transition is invalidated and emits no trade.

This includes both sides being swept on the same bar.

After invalidation, no later reclaim may revive that transition.

### 6. Reclaim confirmation

After an upper sweep, SHORT confirmation requires all of:

- confirmation occurs no later than `max_reclaim_bars` bars after the sweep bar,
- `close < reference_high - reclaim_depth_atr * frozen_atr`,
- `close < open` on the confirmation bar.

After a lower sweep, LONG confirmation requires all of:

- confirmation occurs no later than `max_reclaim_bars` bars after the sweep bar,
- `close > reference_low + reclaim_depth_atr * frozen_atr`,
- `close > open` on the confirmation bar.

`max_reclaim_bars = 0` means the sweep bar itself may confirm a reclaim, provided the bar does not also create an ambiguous double sweep.

A later bar that exceeds `max_reclaim_bars` cannot confirm that sweep.

### 7. Entry and lock

A valid reclaim emits exactly one `+1` LONG or `-1` SHORT signal.

The transition locks immediately after signal emission. No second signal may occur from the same reference/target-session transition.

### 8. Session end

When the target session ends, all unconfirmed sweep state is discarded.

The next qualifying transition begins from a newly constructed reference range.

## Frozen parameter domains

Exactly five strategy dimensions are sampled:

- `transition`: `asia_to_london`, `london_pre_ny_to_new_york`
- `entry_window_bars`: integer 30–180 inclusive
- `sweep_atr`: continuous 0.10–1.00
- `max_reclaim_bars`: integer 0–10 inclusive
- `reclaim_depth_atr`: continuous 0.00–0.50

No RSI, moving average, ADX, MACD, volume, news, weekday, month, spread threshold, volatility regime, trend filter, or discretionary session tuning is allowed in v1.

## Frozen exits

Exit type is sampled independently from the strategy dimensions.

Supported v1 exits:

- stop ATR: `0.75`, `1.0`, `1.5`, `2.0`
- target-R: `1.0`, `1.5`, `2.0`, `3.0`
- time exit minutes: `30`, `60`, `120`, `240`

Catalog exit families:

1. target-R exit: sampled stop ATR + sampled target-R
2. time exit: sampled stop ATR + sampled time exit

No ATR-trailing exit is included in Edge D v1.

The repository's existing execution, sizing, commission, spread, slippage, risk-skip, integrity-mask, and result-accounting semantics remain unchanged.

## Activation diagnostic

A full 10,000-experiment campaign is prohibited until the structural activation diagnostic passes.

The catalog is created first using the frozen seed and budget. The activation diagnostic then evaluates a deterministic catalog-spread sample of exactly 256 experiment rows.

Activation may inspect only structural metrics:

- completed trades,
- risk skip count,
- zero-trade status,
- end-of-data exit count.

Activation must not inspect, rank, filter, or report decisions based on:

- net profit,
- profit factor,
- expectancy,
- win rate,
- drawdown,
- active-day P/L,
- yearly/monthly profitability,
- any other economic metric.

The activation gate PASSES only if all conditions hold:

- at least `205 / 256` sampled configs have `>= 50` completed trades,
- at least `64 / 256` sampled configs have `>= 300` completed trades,
- end-of-data exits are `<= 5%` of all completed diagnostic trades,
- total completed diagnostic trades are `> 0`.

The activation report must persist:

- schema version,
- Edge D identity,
- campaign seed,
- catalog budget,
- deterministic sample indices,
- catalog SHA256,
- feature-data SHA256,
- structural counts/distributions,
- pass/fail decision and reasons.

A FAIL is a valid negative research result. If activation fails, Edge D v1 stops; do not weaken activation thresholds after observing the diagnostic.

## Full campaign gate

The campaign runner must refuse to execute unless a persisted activation report:

- has `passed = true`,
- matches the frozen Edge D family/strategy/sampler identity,
- matches the current experiment catalog SHA256,
- matches the current feature-data SHA256.

This prevents a stale or copied PASS report from authorizing a different dataset or catalog.

If activation passes:

1. run a 20-experiment smoke in the same result directory,
2. verify execution/provenance only,
3. resume the same campaign to all 10,000 rows,
4. do not use smoke profitability as a hidden selection gate.

## Economic and robustness evaluation

The existing Stage-1 promotion rules remain unchanged. Edge D receives no special threshold relaxation.

A candidate must satisfy the repository's frozen Stage-1 requirements, including:

- profit factor `>= 1.10`,
- max drawdown `<= 5%`,
- completed trades `>= 300`,
- after-cost expectancy `> 0`,
- majority profitable years when available,
- existing top-five-trade and best-month concentration controls,
- research integrity checks.

Zero survivors is a valid result.

Trade frequency is not rewarded or capped beyond the minimum sample-size requirement.

## Post-Stage-1 Edge D viability selector

Only Stage-1 robust candidates may enter the Edge D viability selector.

The selector requires:

- `net_profit > 0`,
- `profit_factor >= 1.10`,
- `expectancy_usd > 0`,
- `max_drawdown_pct <= 5.0`,
- finite `final_score`.

It must not impose a minimum/maximum trades-per-day threshold and must allow zero survivors.

At most six candidates may be shortlisted, deterministically ordered by existing robustness score with experiment ID as a stable tie-breaker.
